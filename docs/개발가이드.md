# Splearn 개발가이드

## 기술 스택
- Java 21, Spring Boot 3.5.x
- Spring Data JPA, Spring Web, Bean Validation, Spring Security(crypto)
- DB: H2(개발/테스트), MySQL(운영)
- Lombok, JUnit5, Mockito, ArchUnit, SpotBugs

## 아키텍처
- 헥사고날 아키텍처 + 도메인 모델 패턴
- 의존성 방향: 외부(Actor) → 어댑터 → 애플리케이션 → 도메인 (안쪽으로만)
- ArchUnit `HexagonalArchitectureTest`로 계층 의존성 강제. 위반 시 빌드 실패

### 계층
- **Domain Layer**: 핵심 비즈니스 규칙. 다른 계층/프레임워크에 의존 안 함
- **Application Layer**: 포트(인터페이스)를 정의하고 구현
- **Adapter Layer**: 외부 연동(웹, DB, 메일, 보안). 포트 구현 또는 호출

## 패키지
```
tobyspring.splearn
├── domain
│   ├── member            // 회원 애그리거트 (Member, MemberDetail, Profile ...)
│   └── shared            // 공유 값 객체 (Email ...)
├── application
│   └── member
│       ├── provided      // 드라이빙 포트 (어댑터가 호출하는 서비스 인터페이스)
│       └── required      // 드리븐 포트 (서비스가 필요로 하는 인터페이스)
└── adapter
    ├── webapi            // REST 컨트롤러 (+ dto)
    ├── persistence       // JPA 구현
    ├── integration       // 외부 시스템 연동 (메일 등)
    └── security          // 인증/암호화 (PasswordEncoder 구현)트
```
- 각 도메인/애플리케이션은 `domain/<name>`, `application/<name>/{provided,required}` 로 동일 구조 반복

## 애그리거트와 애플리케이션 컴포넌트 의존관계
- `domain` 패키지 아래 첫 번째 패키지는 각각 하나의 애그리거트이다 이다
- `application` 패키지 아래 첫 번째 패키지는 같은 이름의 애그리거트에 대한 애플리케이션 서비스 패키지이다
- 위에서 구분한 패키지를 **슬라이스(slice)** 라고 부른다
- 하나의 도메인과 애플리케이션 서비스 슬라이스를 묶어 **애플리케이션 컴포넌트** 라고 한다
- 애그리거트는 다른 애그리거트 루트를 직접 참조할 수 있다. 조회 메소드(getter 등)와 레코드 메서드 사용 가능. 
  단, 다른 애그리거트를 변경하는 메서드는 사용할 수 없다
- 애플리케이션 서비스는 다른 애플리케이션 서비스의 기능 제공(provided) 포트의 인터페이스와 DTO를 사용할 수 있다. 
  단, 구현 클래스는 직접 액세스하지 않는다
- 도메인과 애플리케이션 서비스의 슬라이스는 순환 의존성을 허용하지 않는다. 단방향 의존만 가능하다

## 포트 패턴
- **provided**: 드라이빙 포트 인터페이스. 예) `MemberRegister`, `MemberFinder`, `MemberAuthenticator`
  - 구현체는 `application.member` 의 `~Service` 클래스(`MemberModifyService`, `MemberQueryService` ...)
  - 컨트롤러는 구현체가 아닌 포트 인터페이스에 의존한다
- **required**: 서비스가 의존하는 드리븐 포트 인터페이스. 예) `MemberRepository`, `EmailSender`
  - 구현은 adapter 계층(JPA, 메일 발송기)이 담당
- 도메인이 필요로 하는 기술 추상화(예: `PasswordEncoder`)는 도메인에 인터페이스, adapter/security에 구현

## 도메인 모델 관례
- 엔티티는 `AbstractEntity` 상속 → `id`, `equals/hashCode`(HibernateProxy 안전) 공통 제공
- 생성은 필요에 따라 정적 팩터리 메서드 사용: `Member.register(...)`
- JPA용 기본 생성자는 `@NoArgsConstructor(access = PROTECTED)`
- 상태 변경은 의미 있는 도메인 메서드로만(`activate()`, `deactivate()`, `updateInfo()`). setter 금지
- 불변식은 메서드 진입 시 `Assert.state(...)` / `Assert.isTrue(...)` 로 검증
- 값 객체는 `record` + 컴팩트 생성자에서 검증(예: `Email`)
- null 방지: `Objects.requireNonNull(...)`, 패키지 `@NonNullApi`(package-info.java) 적용
- 애그리거트 내부 엔티티 메서드는 package-private 으로 캡슐화(예: `MemberDetail`)

## 애플리케이션 서비스 관례
- 표준 애노테이션 묶음: `@Service @Transactional @Validated @RequiredArgsConstructor`
- 의존성은 `private final` 필드 + 생성자 주입(`@RequiredArgsConstructor`)
- 입력 검증은 포트 메서드 파라미터에 `@Valid` 부착, DTO에 Bean Validation 제약
- 도메인 규칙은 도메인에, 조율,중복검사,트랜잭션 경계는 서비스에
- 조회 전용 서비스와 변경 서비스 분리(`MemberQueryService` / `MemberModifyService`)

## 어댑터 관례
- 웹: `@RestController` + `@RequiredArgsConstructor`, 포트 인터페이스 주입
- 요청/응답 DTO는 `record`. 응답 DTO는 `of(...)` 정적 팩터리로 변환
- 예외 처리는 `@ControllerAdvice`(`ApiControllerAdvice`)에서 `ProblemDetail` 로 통일
- `MemberRepository` 는 Spring Data `Repository` 상속, 필요한 메서드만 선언

## 데이터 전달 객체
- 요청 DTO(`MemberRegisterRequest`)는 `toInfo()` 로 도메인 입력 객체(`MemberRegisterInfo`)로 변환 후 도메인에 전달
- 도메인은 웹 DTO를 직접 받지 않는다

## 테스트 관례
- 테스트 데이터는 `MemberFixture` 등 픽스처 클래스의 정적 메서드로 생성
- 포트 단위 테스트는 `provided`/`required` 패키지 미러링하여 작성
- 웹 계층은 `@WebMvcTest`, 통합은 `@SpringBootTest`
- 아키텍처 규칙 위반은 `HexagonalArchitectureTest` 로 자동 검증
- 빌드 시 SpotBugs 정적 분석 통과 필요

## 네이밍
- 인바운드 포트: 동작 주체 명사(`MemberRegister`, `MemberFinder`)
- 서비스 구현: `<도메인><책임>Service`
- 아웃바운드 포트: `<도메인>Repository`, `<기능>Sender`
- 예외: `<상황>Exception`(`DuplicateEmailException`, `LoginFailedException`)
