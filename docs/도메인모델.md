# Splearn 도메인 모델

## 도메인 모델 만들기
1. 듣고 배우기
2. '중요한 것'들 찾기 (개념 식별)
3. '연결 고리' 찾기 (관계 정의)
4. '것'들을 설명하기 (속성 및 기본 행위 명시)
5. 그려보기 (시각화)
6. 이야기 하고 다듬기 (반복)  

## Splearn 도메인
- 스프런은 회원이 강의를 수강하는 온라인 서비스이다.
- 스프런은 스프링 프레임워크의 철학을 바탕으로 개발되고 운영되며 발전하는 학습 생태계를 목표로 한다.  
  이 생태계를 구성하는 핵심 구성 요소는 학습(성장)하는 회원이다.
    - 그래서 이름이 Spring + Learner = Splearn
    - 유사한 이름으로 인프런이 있다.
- 스프런에서 활동하기 위해서는 회원으로 등록해야 한다.
    - 다만, 회원이 되기 전에도 스프런에 대한 소개와 강의 정보를 살펴볼 수 있다.
    - 강의를 수강하기 위해서는 등록을 완료하고 활동 가능한 회원이 되어야 한다.
    - 등록 신청을 한 뒤 정해진 요건을 충족하면 등록이 완료된다.
    - 등록을 완료한 경우에 프로필 주소, 자기 소개를 등록하거나 수정할 수 있다. 
      - 프로필 주소는 알파벳과 숫자로 구성된 15자리 이내의 중복되지 않은 값
      - 탈퇴한 회원의 프로필 주소와 자기 소개는 수정할 수 없다. 
    - 등록 시간, 등록 완료 시간, 탈퇴 시간을 저장한다. 
- 원하는 회원은 자신이 가진 지식과 경험을 강의라는 형태로 다른 회원에게 제공하는 강사가 될 수도 있다.
    - 회원이 최초로 강사가 되려면 강사 신청과 승인 과정을 거치도록 한다.
    - 승인된 강사는 강의를 생성하고 검수를 거쳐 강의를 공개할 수 있다.
    - 공개된 강의는 회원에게 노출되고, 회원은 이 강의를 수강할 수 있다.
- 수강은 강의를 학습하는 것을 말한다. "내가 수강한 강의는 a이다. 나는 b 강의 수강중이다."
    - 수강을 위해서는 먼저 수강 신청이 필요하다.
    - 수강 신청은 강의의 수강 요건을 요구할 수 있다.
    - 어떤 강의는 강의비 결제를 완료해야 수강이 가능하다.
    - 강사는 강의 수강 기간의 제한을 둘 수도 있다.
- 강의는 영상, 문서와 같은 컨텐츠를 가진 하나 이상의 수업으로 구성 된다.
    - 수업은 갯수가 많을 수 있다. 그래서 수업은 다시 섹션으로 구분한다.
    - 하나의 강의는 여러 개의 섹션과 각 섹션에 속한 수업으로 구성된다.
    - 수업과 섹션은 학습 순서를 가진다.
    - 학습 진도는 매 수업 단위로 기록된다.
    - 강의의 모든 수업의 학습을 마치고 수업 진도가 100%에 도달하면 강의 수강을 완료한 것이다.

## 도메인 모델

### 공통
- 모든 엔티티는 `AbstractEntity` 를 상속해 `id`, `createdAt`, `updatedAt`, `deleted`(soft delete) 를 가진다
- 애그리거트 루트에는 `@AggregateRoot` 를 붙인다
- 정적 팩터리는 `companion object` 에, 내부 엔티티의 생성자·변경 메서드는 `internal` 로 둔다

---
### [회원 애그리거트]

### 회원(Member)
_Aggregate Root_
#### 속성
- `id`: `Long`
- `email`: `Email` - Natural ID
- `nickname`: 닉네임
- `passwordHash`: 비밀번호 해시
- `status`: `MemberStatus` 회원 상태
- `detail`: `MemberDetail` 1:1
#### 행위
- `register(MemberRegisterInfo, PasswordEncoder)`: 회원 등록 (정적 팩터리)
- `activate()`: 등록을 완료시킨다
- `deactivate()`: 탈퇴시킨다
- `verifyPassword(password, PasswordEncoder)`: 비밀번호를 검증한다
- `changePassword(password, PasswordEncoder)`: 비밀번호 변경
- `updateInfo(MemberInfoUpdate)`: 닉네임/프로필 주소/자기 소개 수정
- `isActive()`: 등록 완료 상태 여부 반환
- `ensureActive()`: 등록 완료 상태를 보장
#### 규칙
- 회원 생성후 상태는 등록 대기
- 일정조건을 만족하면 등록 완료가 된다
- 등록 대기 상태에서만 등록 완료가 될 수 있다
- 등록 완료 상태에서는 탈퇴할 수 있다
- 등록 완료 상태에서만 회원 정보를 수정할 수 있다
- 회원의 비밀번호는 해시를 만들어서 저장한다
- 프로필 주소는 중복을 허용하지 않는다. 기존 프로필 주소를 제거할 수는 있다
- 이메일은 중복을 허용하지 않는다 (`UK_MEMBER_EMAIL_ADDRESS`)

### 회원 상세(MemberDetail)
_Entity_
- `id`: `Long`
- `profile`: `Profile?` 프로필 주소. 모든 회원이 고유한 프로필 주소를 가져야 한다
- `introduction`: 자기 소개
- `activatedAt`: 등록 완료 일시
- `deactivatedAt`: 탈퇴 일시
- 등록 일시는 `AbstractEntity.createdAt` 을 사용한다
#### 행위 (internal, Member 를 통해서만 호출)
- `create()`: 회원 상세 생성 (정적 팩터리)
- `activate()`: 등록 완료 일시 저장. 이미 저장되어 있으면 예외
- `deactivate()`: 탈퇴 일시 저장. 이미 저장되어 있으면 예외
- `updateInfo(MemberInfoUpdate)`: 상세 정보 수정

### 회원 상태(MemberStatus)
_Enum_
#### 상수
- `PENDING`: 등록 대기
- `ACTIVE`: 등록 완료
- `DEACTIVATED`: 탈퇴

### 회원 등록 정보(MemberRegisterInfo)
_Value Object (data class)_
#### 속성
- `email`: 이메일
- `nickname`: 닉네임
- `password`: 비밀번호
- 입력 길이 제약(닉네임 5~20자, 비밀번호 8~100자)은 application 의 `MemberRegisterRequest` 에서 검증한다

### 회원 정보 수정(MemberInfoUpdate)
_Value Object (data class)_
#### 속성
- `nickname`: 닉네임
- `profileAddress`: 프로필 주소
- `introduction`: 자기 소개
- 입력 검증은 application 의 `MemberInfoUpdateRequest` 에서 한다

### DuplicateEmailException
_Exception_ - 이메일 중복

### DuplicateProfileException
_Exception_ - 프로필 주소 중복

### 비밀번호 인코더(PasswordEncoder)
_Domain Interface_ - 구현은 `adapter:outbound:security`
#### 행위
- `encode()`: 비밀번호 암호화하기
- `matches()`: 비밀번호가 일치하는지 확인

### 프로필 주소(Profile)
_Value Object (`@Embeddable` data class)_
#### 속성
- `address`: 프로필 주소 (소문자·숫자, 최대 15자. 빈 값 허용)
#### 행위
- `url()`: `@`를 접두어로 붙인 프로필 URL 반환

### 이메일(Email)
_Value Object (`@Embeddable` data class)_
#### 속성
- `address`: 이메일 주소 (이메일 형식)

### 회원 등록됨(MemberRegisteredEvent)
_Domain Event_ - 외부 이벤트
- `memberId`: 등록된 회원 id
- 회원 등록 후 outbox → Kafka 로 발행되고, consumer 가 가입 환영 메일을 보낸다

### [강사 애그리거트]

### 강사(Instructor)
_Aggregate Root_
#### 속성
- `id`: `Long`
- `member`: `Member` 회원 - 1:1
- `status`: `InstructorStatus`

#### 행위
- `apply(member)`: 강사 신청 (정적 팩터리)
- `approve()`: 강사 신청 승인
- `reject()`: 강사 신청 거절
- `isActive()`: 승인 완료 상태인가?
- `ensureActive()`: 승인 완료를 보장

#### 규칙
- 등록 완료 상태의 회원만 강사 신청을 할 수 있다
- 신청 대기 상태에서만 승인·거절할 수 있다

### 강사 상태(InstructorStatus)
_Enum_
#### 상수
- `PENDING`: 신청 대기
- `ACTIVE`: 승인 완료
- `REJECTED`: 신청 거부

### [강의 애그리거트]

### 강의(Course)
_Aggregate Root_
#### 속성
- `id`: `Long`
- `title`: `String` 강의 제목
- `instructor`: `Instructor` 강사
- `status`: `CourseStatus` 강의 상태
- `detail`: `CourseDetail`
#### 행위
- `Course(instructor, title, description)`: 강의 생성 - 제목과 강사만 필수
- `submitForReview()`: 검수 신청
- `publish()`: 강의 공개
- `archive()`: 강의 보관
- `updateInfo(CourseUpdateInfo)`: 강의 정보 수정
- `isPublished()`, `ensurePublished()`: 공개 상태 확인·보장
#### 규칙
- 승인 완료 상태의 강사만 강의를 생성할 수 있다
- 같은 강사는 같은 제목의 강의를 만들 수 없다 (`UK_INSTRUCTOR_TITLE`)
- 상태는 `DRAFT → IN_REVIEW → PUBLISHED → ARCHIVED` 순으로만 바뀐다
- 검수 신청은 필수 조건을 모두 만족해야 가능하다
  - 강의 소개 필수
  - 커리큘럼이 유효해야 한다 (application 의 `CourseValidator` 가 `CurriculumValidator` 로 확인, 공개 시에도 확인)
- 강의 생성 후 `CourseCreatedEvent` 로 커리큘럼이 함께 생성된다

### 강의 생성됨(CourseCreatedEvent)
_Domain Event_ - 내부 이벤트
- `courseId`: 생성된 강의 id
- 같은 트랜잭션 안에서 처리되어 해당 강의의 커리큘럼을 만든다

### 강의 상태(CourseStatus)
_Enum_
#### 상수
- `DRAFT`: 초안
- `IN_REVIEW`: 검수 신청
- `PUBLISHED`: 공개
- `ARCHIVED`: 보관

### 강의 상세(CourseDetail)
_Entity_
#### 속성
- `description`: 강의 소개
- `publishedAt`: 공개 일시
- `archivedAt`: 보관 일시
- 생성 일시는 `AbstractEntity.createdAt` 을 사용한다
#### 행위 (모두 internal, Course를 통해서만 호출)
- `CourseDetail(description)`: 생성 일시 저장
- `publish()`: 공개 일시 저장
- `archive()`: 보관 일시 저장
- `updateInfo(CourseUpdateInfo)`

### [수강 애그리거트]

### 수강(Enrollment)
_Aggregate Root_
#### 속성
- `id`: `Long`
- `member`: `Member` 수강 회원
- `course`: `Course` 강의
- `status`: `EnrollmentStatus` 수강 상태
- `completedAt`: `LocalDateTime` 수강 완료 일시 (완료 전에는 `null`)
- 수강 신청 일시는 `AbstractEntity.createdAt` 을 사용한다
#### 행위
- `enroll(member, course)`: 수강 신청 (정적 팩터리). 상태를 `ENROLLED`로 둔다
- `startStudying()`: 학습을 시작한다
- `complete()`: 수강을 완료한다. 완료 일시를 저장한다
#### 규칙
- 등록 완료 상태의 회원만, 공개된 강의에만 수강 신청할 수 있다
- 수강 신청 직후 상태는 `ENROLLED`(수강 신청 완료)이다
- `ENROLLED` 상태에서만 학습을 시작할 수 있다
- `STUDYING` 상태에서만 수강을 완료할 수 있다
- 한 회원은 같은 강의를 중복해서 수강 신청할 수 없다 (`UK_ENROLLMENT_MEMBER_COURSE`)

### 수강 상태(EnrollmentStatus)
_Enum_
#### 상수
- `ENROLLED`: 수강 신청 완료
- `STUDYING`: 학습 중
- `COMPLETED`: 수강 완료

### [커리큘럼 애그리거트]

### 커리큘럼(Curriculum)
_Aggregate Root_
#### 속성
- `id`: `Long`
- `course`: `Course` 강의 - 1:1
- `sections`: `List<Section>` 섹션 목록 - 순서 있음
#### 행위
- `Curriculum(course)`: 생성
- `addSection(title)`: 섹션을 맨 끝에 추가
- `addSection(sectionIndex, title)`: 지정 위치에 섹션 삽입(중간 삽입 가능)
- `addLesson(sectionIndex, title)`: 지정 섹션에 수업 추가
- `updateSectionTitle(sectionIndex, title)`: 섹션 제목 수정
- `updateLessonTitle(sectionIndex, lessonIndex, title)`: 수업 제목 수정
- `removeLesson(sectionIndex, lessonIndex)`: 수업 삭제
- `removeSection(sectionIndex)`: 섹션 삭제
- `moveLesson(fromSection, fromLesson, toSection, toLesson)`: 수업 이동
- `validate()`: 등록된 섹션과 수업이 구성 조건을 만족하는지 확인
- `allLessons()`: 섹션 순서대로 전체 수업 반환
- `firstLesson()`: 첫 수업 반환
- `nextLesson(lesson)` / `nextLesson(lessonId)`: 다음 수업 반환

#### 규칙
- 강의 생성 시(`CourseCreatedEvent`) 함께 생성된다
- 섹션 삽입 인덱스는 `[0, 섹션 수]` 범위여야 한다(맨 끝 삽입 허용)
- 마지막 남은 섹션은 삭제할 수 없다
- 섹션 삭제 시 수업은 이전 섹션 끝으로 이동한다(첫 섹션이면 다음 섹션 맨 앞)
- 수업·섹션 삭제는 soft delete 로 처리한다 (컬렉션에서 제거하고 `deleted = true` 표시. 이동한 수업은 삭제되지 않는다)
- 수업의 전체 순서는 섹션 순서 + 섹션 내 순서로 결정된다
- 빈 섹션은 첫/다음 수업 탐색 시 건너뛴다
- 최종 확인 조건은 최소 1개 섹션과 1개 수업이 있어야 하고, 수업이 없는 빈 섹션은 존재하면 안 된다 (`InvalidCurriculumException`)

### 섹션(Section)
_Entity_
#### 속성
- `id`: `Long`
- `curriculum`: `Curriculum` - N:1
- `title`: 섹션 제목
- `lessons`: `List<Lesson>` 수업 목록
#### 행위 (internal, Curriculum 을 통해서만 호출)
- `addLesson(title)`, `addLesson(index, lesson)`: 수업 추가
- `updateTitle(title)`
- `updateLessonTitle(index, title)`
- `removeLesson(index)`: 수업 제거
- `moveAllLessonsTo(target, index)`: 모든 수업을 다른 섹션으로 이동

### 수업(Lesson)
_Entity_
#### 속성
- `id`: `Long`
- `section`: `Section` - N:1
- `title`: 수업 제목
#### 행위 (internal, Curriculum 을 통해서만 호출)
- `updateTitle(title)`
- `moveTo(section)`

### 진도
_미구현_
